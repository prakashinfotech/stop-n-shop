## User Request
Debug and fix why no products appear in the browser after the full frontend build.

## Generated Solution
Identified three root causes and applied fixes across five API files:
1. Program.cs — UseHttpsRedirection() ran unconditionally, causing HTTP 307 redirects that Vite proxy cannot follow.
2. Program.cs — No global camelCase JSON policy; all properties serialized in PascalCase (Name not name), breaking every frontend type binding.
3. All DTOs — Properties whose names differed from frontend expectations even after camelCase (MRP->mRP, BrandName->brandName, DiscountPct->discountPct) required [JsonPropertyName] attributes. OrderDetailDto required computed nested properties (Address, Summary) since Dapper populates flat fields but the frontend expects nested objects.

## Files Modified
- api/Program.cs — conditional HTTPS redirect (dev only); global JsonNamingPolicy.CamelCase
- api/DTOs/ProductDtos.cs — [JsonPropertyName] on MRP, BrandName, DiscountPct, ImageUrl, SortOrder, SizeLabel, StockQuantity, ColorName, ColorHex, DiscountValue; added OfferCount, CategoryId, SubCategoryId fields
- api/DTOs/CartOrderDtos.cs — [JsonPropertyName] on all mismatched fields; added OrderShippingAddressDto + OrderSummaryDto; OrderDetailDto computed Address/Summary properties hide flat Dapper fields from JSON
- api/DTOs/CatalogueDtos.cs — [JsonPropertyName] on CategoryId/CategoryName/CategorySlug and sub-category/product-type fields to match id/name/slug
- api/DTOs/AuthDtos.cs — added Role property to UserProfileDto

## Errors/Conflicts
- After removing Gender from ProductListItemDto, ProductRepository.cs line 38 failed: CS0117 does not contain a definition for Gender — fixed by re-adding with [JsonIgnore].

## Resolution
dotnet build passes with 0 warnings, 0 errors.

## Architectural Notes
- [JsonPropertyName] gives Dapper the real C# property names while System.Text.Json outputs the renamed keys — no stored procedure or repository changes needed.
- [JsonIgnore] on flat address/totals in OrderDetailDto combined with computed Address/Summary properties lets Dapper populate the object while the JSON output matches the nested frontend shape.
- JsonNamingPolicy.CamelCase only lowercases the first character — TotalMRP becomes totalMRP (correct), but MRP becomes mRP (wrong) — explicit overrides still required for all-caps abbreviations.
